UI for MCP Apps, released like code.

genui adds forms, charts and your own components to your MCP server. They render inside Claude, ChatGPT and other MCP Apps hosts, work with the tools you already have, and move from beta to stable when you say so.

Get early access See how it works

Built on the MCP Apps standard and the official MCP TypeScript SDK.

How it works

Three steps, and the first one is a single function call in the server you already run.

  1. 1 Mount the SDK in your server

    One call adds forms, charts, your recipes and your custom components as tools, from the release channel you pick. 

    await mountGenUI(server, {
  registry,
  channel: "stable",
});

  2. 2 The model builds the UI

    It picks a form or chart and fills in what it knows. Selects search your tools as people type, and submit errors from your tool show next to the field. 

    {
  "name": "customer",
  "type": "resource_select",
  "source": {
    "toolName": "search_customers"
  }
}

  3. 3 Release from the registry

    Publish to beta from CI, try it in the chat, then promote to stable. Running servers switch over without a restart. 

    $ genui publish .
# 1.3.0 is on beta
$ genui promote order-summary
# 1.3.0 is on stable

What's included

The parts every in-chat view needs, so your team writes the component and not the plumbing around it.

Forms
Text, numbers, dates, switches and selects, including selects that search your own tools. Errors from your submit tool appear next to the field, and the values stay put.
"type": "resource_select"
Charts
Line, bar, area and pie. Pass rows inline, or let the chart call your tool so large or private data stays out of the model's context. Refreshes pause while the chart is off screen.
"data": { "source": … }
Recipes
Forms your business owns. Fields, validation and the submit tool are fixed; the model only picks the recipe and pre-fills values. Each recipe is also a slash command.
/create_order
Custom components
Write your own with @genui/kit in plain TypeScript or the framework you use. Props are a Zod schema, and the build is a single HTML file ready to publish.
defineComponent({ … })
Theme
Views follow the host's colors, fonts and dark mode. Set your primary color, accent, corner radius and chart colors once for the workspace, with a live preview in the chat.
--genui-primary
Loading states
Fields appear while the model is still writing. Searches debounce and cancel, submits can't fire twice, and failures tell the model what went wrong.
streaming → ready

Beta and stable channels for the chat

Every version is immutable, and removing a prop needs a major version. Give beta to your team or a few customers, promote when it's ready, and roll back if it isn't.

Old messages keep rendering the version they were made with, so a release never breaks a conversation that already happened.

The registry is an MCP server too. Admins promote, roll back and edit the theme from views inside Claude or ChatGPT, and those buttons only run when a person clicks them.

Bundles, recipes, theme

genui registry

Stores components, recipes and your theme. It never sees a tool call or its result.

  • Versions that never change

    A published version is immutable. Breaking prop changes need a major version, and a bad release rolls back in one click.

  • People confirm, not the model

    Promote, roll back and theme changes are hidden from the model. They run only from a click in the view.

  • Run the registry yourself

    One Node process and a SQLite file. Sign in with GitHub, Google or your company's OIDC provider.
