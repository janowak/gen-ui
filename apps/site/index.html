How it works

No server of your own to run.

  1. 1 Build your components

    TypeScript with @app-mcp/kit, in any framework. Workflows are Markdown next to them. 

    defineComponent({
  name: "rating",
  props: z.object({ … }),
});

  2. 2 Publish

    One command puts them in your workspace. Add its address in Claude or ChatGPT to try the flow yourself. 

    $ app-mcp publish
# serves rating 1.3.0

  3. 3 Customers connect

    They add the same address as a connector. New versions reach running chats without a restart. 

    Settings → Connectors → Add
https://api.app-mcp.com
  /w/<workspace>/mcp

Get started with one prompt

Paste this into Claude Code, Cursor, Codex or any coding agent in your project. You click Allow once; it builds and publishes your first component and hands you two links.

Prompt for your coding agent 
Set up app-mcp in this project. Run `npx @app-mcp/cli guide` and follow it:
sign in, build my first component (ask me what it should show), check it and publish it.
Finish with my admin link and the link my users add.

Prefer to do it by hand? Run npx @app-mcp/cli login, then init and publish. The setup guide has the details.

Features

You write the component. app-mcp handles everything around it.

Your components
A seat picker, a quote builder, a rating: whatever your flow needs. Any framework, props as a Zod schema.
Workflows
Playbooks in your own words, published with your components. Ones with params become slash commands.
Forms and charts, built in
For everything you haven't built yet: inputs, dates, selects; line, bar, area and pie charts.
Your theme
Views follow the host's fonts and dark mode, with your colors, radius and chart palette on top.
Environments
Staging next to prod in the same chat, each with its own address, versions and theme. Ship a tested version without rebuilding.
Live updates
New versions reach running chats without a restart, and old messages keep the exact version they were made with.
Streaming states
Fields appear while the model is still writing. Submits can't fire twice, and failures tell the model what went wrong.
Inside your own app
Embed an assistant with the same views and workflows, on your model and your sign-in, with @app-mcp/host.
